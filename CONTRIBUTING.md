\# Contributing Guidelines



\## Branch naming

\- `feature/<name>` for new features (e.g. `feature/home-screen`)

\- `fix/<name>` for bug fixes

\- `docs/<name>` for documentation changes



Never commit directly to `main`.



\## Commit messages

Write short, clear messages in the present tense:

\- Good: "Add service card component"

\- Bad: "stuff", "update", "fix"



\## Workflow

1\. Pick an open Issue and assign yourself.

2\. Create a branch from the latest `main`.

3\. Make small, focused commits.

4\. Push your branch and open a Pull Request.

5\. Write `Closes #<issue number>` in the PR description.

6\. Get at least one teammate to review, then merge.

7\. Pull the latest `main` before starting your next task.



\## Pull request checklist

\- The app runs without errors

\- I tested my changes on a phone or emulator

\- I included a screenshot (for UI changes)
